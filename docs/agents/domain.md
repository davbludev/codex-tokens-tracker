# Domain docs

Use a single-context layout: root `CONTEXT.md` and `docs/adr/`.

Before exploring the codebase, read `CONTEXT.md` and relevant ADRs.
If a root `CONTEXT-MAP.md` exists later, follow its pointers to
the contexts relevant to the task.

If domain docs are absent, proceed silently. The domain-modeling
skill creates them when terms or decisions are resolved.

Use the glossary's vocabulary when naming domain concepts.
If a needed term is missing, reconsider the term or note the gap
for domain-modeling.

Explicitly identify any proposal that contradicts an existing ADR,
and explain why the decision should be reopened.
